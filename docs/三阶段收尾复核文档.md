本次收尾修改与三轮返工完成项：
1. **取消拒绝保护、双向竞态收敛与权威取消事实结构化（`ota-common` / `ota-supplier` / `ota-order`）**：
   - `BookingFlowContracts.SupplierResult` 结构化携带 `cancelRequestNo`、`priorState`、`priorEventId`；完全删除依赖 `reason.contains(...)` 自由文本判断权威状态的分支，`reason` 仅用于展示与诊断；
   - 供应侧 `SupplierBookingStore.mergeCancel` 固定按 `supplier_booking_request` → `supplier_booking_cancel` 顺序加锁并比较已有取消结果，在 `supplier_booking_cancel` 中分别持久化首次权威事实 `result` 与矛盾证据 `conflict_result`（显式状态 `CANCEL_CONFLICT`），并通过 `supplier_booking_delivery.depends_on_id` 在 `pendingDeliveries` 与 `claim` SQL 层强制前序投递已 `SENT`；
   - 订单侧 `booking_order` 新增 `cancel_fact` 与 `cancel_conflict` 独立持久化字段，`BookingStore.inbox` 与 `BookingFlowService.applyInbox` 严格校验归属、取消请求号、`priorState`/`priorEventId` 及确定性组合；原事实作为独立事件收敛，`CANCEL_CONFLICT` 仅记录矛盾并置 `REVIEW_REQUIRED`，绝不触发 `ports.cancelled` 或退款；当冲突证据先到且 `cancel_fact` 尚未核实时，订单保持现有配额与资金，并通过 `work()` + `verifyMissingCancelFact` 按原取消请求号查证恢复经核实的原事实。
2. **冻结快照完整性（`ota-inventory` / `ota-order`）**：`RateQuoteService.snapshot` 与 `RateModels.View` 补齐 `hotelName`、`roomTypeName` 传递；`RateModels.Binding` 的相等性校验排除展示名字段（保留供应身份、映射 ID、来源版本与房型物理属性校验），确保报价生成后修改酒店名称或切换静态主来源仍可正常建单，且建单、查询、渠道通知均保持原报价冻结名称与身份。
3. **付款期限与资金保护（`ota-order`）**：验证并加固 `AFTER_CONFIRM` 首次确认起算付款期限、重复确认回调与恢复不延长期限、确认后超时未付转 `REVIEW_REQUIRED`；补齐退款 `REVIEW_REQUIRED` 状态防覆盖保护及 `BookingMapper.xml` 待处理供应回调立即唤醒调度。
4. **对账查证准确性（`ota-order`）**：`BookingFlowService.reconcile` 对远端查单超时（`UNAVAILABLE`）、未知（`UNKNOWN`）、归属或确定性非法（`INVALID_RESPONSE`）以及本地待复核状态统一标记 `difference=true`，不再将本地与远端同为 `UNKNOWN` 或错单响应误判为一致。
5. **稳定通知版本绑定、版本替换（`SUPERSEDED`）与反向自测（`ota-channel` / `scripts/booking-flow-smoke.py`）**：`ChannelNotificationDatabaseTest` 新增旧版本错误 ACK 后新版本到达转为 `SUPERSEDED` 且新稳定版本耗尽重放送达的真实测试；`scripts/booking-flow-smoke.py` 对回环地址内置 `ProxyHandler({})` 直连 opener，在建单前按 `outOrderNo` 预注册故障规则，先验证 `WAIT_PAYMENT` 旧版本错误 ACK 后被付款后新版本替代为 `SUPERSEDED`（绝不将 `SUPERSEDED` 当作 `DELIVERED`），再显式绑定付款后稳定目标版本（`orderId + version + eventId`）验证错误 ACK 恢复（`版本-03`）与重试耗尽进 `DEAD`、`403` 越权拒绝、授权重放审计及最终 `DELIVERED`（`版本-04`），且自包含 `MockCluster` 实现版本游标与 `SUPERSEDED` 语义并通过 `--verify-negatives` 正反向自测。
