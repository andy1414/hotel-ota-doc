# 多来源报价第三阶段实施记录

日期：2026-10-29。承接来源酒店和房型映射，交付独立价格计划、共享配额池、渠道计划授权、报价凭证和本地占用状态机。

## 1. 本批交付边界

- 新流程为内部接口，不接收未经渠道接入层认证的公开请求。
- 已实现“报价 → 验价并占用 → 本地配额核销/释放 → 超时释放”。
- 尚未将旧订单创建、支付和取消接口切到此流程，也未调用真实供应商预订或资金接口。
- 后续已明确订单分为即时确认与异步确认。本批报价尚未保存确认模式/确认时限，30分钟占用自动释放也未与异步订单确认协调；完成这些扩展前不能用于真实异步下单。目标规则以需求设计第9章为准。
- 上述缺口的后续落地见[即时与异步确认第四阶段实施记录](即时与异步确认第四阶段实施记录.md)：已增加确认快照和活跃履约配额保护；供应调用、查单及平台订单接入仍待完成。
- 本地BOOKED表示配额已核销，不表示集团/第三方供应商已确认，也不表示真实支付成功。
- 旧inventory_price_stock与旧订单链路保留，不自动转换旧房量，不猜测原记录属于哪个真实价格计划。

## 2. 数据模型与来源

价格码、每日价格及预订政策参考 `/Users/fuxinwei/work/db/hotel_order1.txt` 的room_price和 `api_hotel.txt` 的product/order_product。共享库存池、供货能力、授权版本、报价凭证及订单占用流水为本次新增。

| 对象 | 本批含义 |
| --- | --- |
| partner_rate_capability | 单独声明供应商可以提供PLATFORM_QUOTA；有静态数据不代表有供货能力 |
| inventory_rate_plan | 按来源房型、合同、价格码、入住人数唯一；带版本、启停与政策 |
| inventory_pool_daily | 按来源酒店、合同、共享池编号、日期唯一；维护总量、冻结和已订 |
| rate_price_daily | 价格计划每日含税供货价及池关联；多个计划可引用同一个池 |
| channel_rate_access | 按渠道+计划显式授权，附启停、计划级加价系数及版本；默认拒绝 |
| inventory_quote | 不透明报价ID、原始来源/政策/逐日金额快照、有效期、状态及绑定订单号 |
| quote_pool_allocation | 当前报价/订单在每个池的占用数量和状态，避免操作其他订单聚合冻结量 |

供应商、来源、平台酒店/房型必须已登记并确认。新价库在当前共库部署下读取这些关系；拆库时须替换为版本化来源契约，不能直接复制这组跨表查询。

## 3. 首批支持的明确业务口径

- 币种固定CNY、支付类型固定PP；上传的supplyPrice必须是CNY含税含必要服务费的供货价，不自动换汇或叠加隐含佣金。
- 库存模式仅为平台独立配额PLATFORM_QUOTA。供应商实时可用量快照不能直接写成该配额。
- 一个计划覆盖一次报价的全部入住晚，报价不跨计划/供应商拼夜。
- 支持1～5人价格计划、最多20间/次、最多30晚，支持最小/最大连住晚数、提前预订天数与早餐数量快照。
- 取消政策只支持NON_REFUNDABLE或FREE_UNTIL；后者截止时间按入住日北京时间14:00减配置小时计算，不从酒店静态免费取消字段推导。
- 完整周控、预订时段、阶梯取消、现付、包价、小时房及真实退款暂未接入。未支持的供货合同不应按默认PP/CNY上传。
- 名称相似不能替代房型等价证据。报价时再次核对来源与平台房型的床型、人数、窗户和面积，防止确认后的静态变化使旧映射继续供货。
- 床型比对保留尺寸小数点，不把1.8m和18m清洗成相同字符串；未知床型不作为等价证据。

## 4. 授权与计价

1. 校验来源映射、平台酒店/房型发布与有效状态、静态来源启用及独立配额供货能力。
2. 校验渠道已登记上线，编码使用登记值的准确大小写。
3. 必须存在该渠道到当前计划的启用授权；单纯拥有加价规则不能视为可售。
4. 计划级系数首批允许0～10，售价为供货价×(1+系数)。每日单间先按两位小数HALF_UP舍入，再乘间数并汇总。
5. 不通过旧ChannelPricingService的异常零加价降级，也不静默将缺失规则当零价/零系数。
6. 渠道视图返回售价、权益及有效期，不返回采购价、供应商身份和加价系数；这些数据保存在内部快照。

新授权采用清晰的计划作用域，不自动继承旧六类规则，避免历史partner_code集团语义不明时错误迁入供应商授权。六维规则向新计划授权的发布机制仍需后续实现。

旧规则同时修正两点：价格码规则4保存时不再清空partnerCode，并要求填写来源范围；预览缺少来源/品牌/酒店/价格码维度时跳过依赖该维度的规则，避免动态SQL把NULL条件省略后跨来源累加。历史无来源价格码规则不自动回填，需人工明确范围。

## 5. 凭证、验价与占用

- 报价ID为服务端生成的不透明UUID，快照存数据库，调用方不能提交或修改快照内容。
- 报价默认5分钟有效。持凭证占用时重新验证来源和房型映射、计划/授权版本、逐日价格版本、金额、合同及池归属。
- 金额不同、资料或价格变化、渠道停用、映射解除、报价过期等情况返回冲突/不可用，要求重新报价。
- 所有入住晚在同一个本地事务冻结；任一天失败则回滚之前的冻结、占用流水和报价状态。
- 库存池按ID排序锁定，SQL带可用量/冻结量条件，数据库约束保证total>=frozen+booked。
- 同订单重试同报价不重复冻结；同报价不能绑定另一个订单，一个订单号也不能同时绑定两个报价。
- 冻结后默认30分钟占用期，核销不能使用已过期占用；订单接入时须对齐支付时限，不能继续沿用互不协调的超时规则。
- 释放和核销根据该报价的占用流水操作，不依赖当前是否仍可售；来源下架后仍能恢复原占用。
- 定时任务每分钟扫描至多100笔过期占用，各笔独立事务释放；多实例依靠行锁和终态幂等。失败保留原状态供下次重试并记录错误。
- 本批不把BOOKED配额按“释放冻结”方式退回，退款/退房量需要后续独立售后流程。

## 6. 版本化同步

- 供货能力、计划、池配额、每日价格和渠道授权分别有递增版本。
- 同版本同内容幂等，同版本不同内容或旧版本覆盖均拒绝。
- 池配额更新只变更total，不清零已有frozen/booked；新配额不得低于已有占用。
- 每日价格只能绑定同来源酒店、同合同、同营业日的池；跨供应商池引用被拒绝。
- 价格或授权变更不重写旧报价快照；旧凭证无法悄悄按新规则成交。

## 7. 内部接口与启用条件

全部接口前缀 `/internal/rates`，要求 `X-OTA-Internal-Token`。该凭据属于可信内部管理/渠道接入调用方，不可发给外部渠道。

| 方法/路径 | 用途 |
| --- | --- |
| POST `/capabilities` | 登记/启停独立配额供货能力 |
| POST `/plans` | 版本化登记价格计划及政策 |
| POST `/pools` | 版本化更新每日配额池，返回池ID |
| POST `/prices` | 将计划每日价格关联到明确池ID |
| POST `/access` | 显式授权渠道计划及系数 |
| POST `/quotes` | 创建渠道报价；channelCode/planId/checkIn/checkOut/quantity |
| GET `/quotes/{id}` | 按所属channelCode读取渠道视图 |
| POST `/quotes/{id}/hold` | 验价及占用；channelCode/orderId/expectedTotal |
| POST `/quotes/{id}/book` | 核销本地冻结配额；channelCode/orderId |
| POST `/quotes/{id}/release` | 释放本订单冻结配额；channelCode/orderId |

`orderId`要求使用平台生成的全局订单ID；外部渠道订单号需在订单接入层按渠道作用域建立幂等关系，不能直接当作全局ID。

启用前按顺序完成005～008迁移，其中008为本批新增脚本。配置 `INVENTORY_QUOTES_ENABLED=true` 和非空 `INVENTORY_QUOTES_INTERNAL_TOKEN`。默认关闭；本次未连接运行数据库，也未自动开放新供货链路。

## 8. 验证证据与限制

- 新增H2测试依赖，仅test作用域；使用真实RateMapper、独立内存数据库和多连接事务，不占用本机3306。
- 数据库回归覆盖逐日舍入、显式授权、采购数据隐藏、重报价、跨供应商价格码隔离、共享池并发、第二晚失败整单回滚、重复核销、订单唯一占用、映射撤销后过期释放、配额缩减保护及床尺寸精度。
- H2测试结构用VARCHAR承载JSON，验证Mapper操作和事务行为，不证明MySQL原生JSON、完整DDL及锁行为完全等价。
- 尚需真实MySQL迁移、静态映射并发纠错与报价之间的锁竞争验证；发生死锁/锁超时时上层应按可重试失败处理，不把数据库异常当成功。
- 尚未接入渠道API身份认证、平台订单持久化、真实支付、供应履约、订单Outbox和供货对账。管理前端、完整规则发布和缓存优化也未在本批完成。
