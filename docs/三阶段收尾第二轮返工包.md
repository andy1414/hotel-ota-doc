## 二、返工一：取消冲突证据不得触发错误副作用

优先级：P1，阻断。对应复核-01。

### 问题与触发

供应保存先到的明确取消结果，冲突时把原结果和相反结果分别投递订单。仅依靠 `ORDER BY next_attempt_at,id` 不能保证到达顺序：原拒绝事件转发失败延期后，Job 继续投递 CANCELLED；多实例也可以分别领取两个事件。订单先收到取消成功时可能归还配额并退款，后收到拒绝只能进入复核，不能撤回已经发生的动作。

重点位置：`ota-supplier` 的 `SupplierBookingStore.mergeCancel/enqueue`、`SupplierCallbackDeliveryJob`、`SupplierBookingMapper.xml`；`ota-order` 的 `BookingFlowContracts` 使用处、供应收件箱、`BookingFlowService.applyInbox` 与资金库存调用。公共契约实际位于 `ota-common`。

### 必须实现

1. 持久化保存原明确事实和矛盾证据。冲突证据不得作为独立取消成功指令执行。
2. 实施方选择并说明完整方案：让订单识别权威事实与冲突证据，或建立持久化同订单顺序及前序确认机制。方案必须覆盖同步取消 RPC、异步回调、转发重试及恢复，不能只保护某一条路径。
3. 若采用有序投递，前序确认门槛必须跨实例、租约过期和重启有效；前序只是 HTTP 接收成功还是已完成事实收敛，应定义清楚。不能靠 SQL 排序、事件 ID 前缀或固定延迟代替正确性。
4. 原事实为拒绝时，任何乱序冲突都不得触发取消成功、退款或配额归还；订单应保留有效预订并进入人工复核。
5. 原事实为取消成功时，保留已经确认的取消及资金库存事实；后到拒绝只追加矛盾并进入复核，不逆转已执行动作，不重复退款。
6. 同义重复、UNKNOWN、内容冲突、换号取消保持既有保护。错误归属和未知事件类型不得触发副作用。
7. 网络调用在本地事务外；业务 SQL 在 XML。新增字段、事件类型或顺序标识应同步初始化 SQL、测试结构、接口契约、校验和验收脚本；当前测试数据无需存量兼容回填。

### 必交测试

使用可控屏障、真实 XML 和独立事务，至少包含：

- 原拒绝首投失败，后续相反结果可被调度时，订单无退款和配额归还。
- 两个 Job 实例交错执行，同订单事件不会绕过保护。
- 原事件发送后 ACK 丢失、重复投递、租约过期、进程重建恢复。
- 同步 RPC 与异步事件交错，分别以拒绝和成功为原事实。
- 最终人工复核状态、持久化原事实、矛盾证据及对外查询一致。

断言供应请求/取消次数、事件身份、订单资金状态、真实库存分配数量和退款笔数。只验证排序后的事件列表或手工顺序调用 inbox 不足以关闭本问题。外部资金限显式 TEST，不连接真实支付机构。

## 三、返工二：通知故障验收必须可判失败

优先级：P2，验收阻断。对应复核-02。

位置：`scripts/booking-flow-smoke.py` 通知故障场景。当前固定等待两秒，既未证明错误 ACK 实际发生，也未把故障订单纳入最终送达等待；未执行重试耗尽和人工重放。

必须修改：

1. 在故障订单通知可能发出前建立可控故障规则，避免注册故障晚于首次投递。以条件等待确认收到指定订单、事件和版本，并返回错误事件号 ACK。
2. 查询或观察投递事实，证明错误 ACK 未被判成功；不能只记录接收器收到请求。等待有界，超时失败。
3. 恢复正确 ACK 后，等待该故障订单对应事件真实投递成功。最终 PASS 必须包含此项，不只检查两笔正常订单。
4. 独立场景验证有界重试耗尽、失败状态、管理端人工重放、操作审计和最终正确 ACK。明确验证的是 order→channel 还是 channel→外部渠道投递层，两层证据不得混用；没有必要查询能力时补充受保护入口或独立数据库验收步骤。
5. 按订单/事件关联接收、错误 ACK、正确 ACK 和最终状态；共享接收器状态保证线程安全。脚本异常、等待超时、错误状态均非零退出，禁止在 finally 或异常吞掉后输出 PASS。
6. 可配置短测试重试间隔和上限仅限显式测试配置，不削弱生产重试、鉴权和通知地址安全规则。签名、token 不输出到日志。

验证脚本：故意永不发送故障订单通知、始终错误 ACK、重放不送达时分别必须失败；完整故障恢复场景才可成功。使用事件等待替代固定 sleep 作为成功依据。

## 四、返工三：实际跨服务验证与证据

对应复核-03，验收门槛未满足。

在明确的独立测试环境运行修正后脚本，覆盖正常即时/异步闭环、重复下单、拒绝取消、未知提交恢复、通知故障与重放。取消乱序需有可控真实事务测试；HTTP 是否覆盖该时序单独记录。

环境具备前只做干跑；实际重建必须显式确认目标专用测试库并使用脚本执行参数，不默认清理远端。缺少环境时填写具体依赖和未验证项，保持 No-Go，不将脚本准备完成写为联调成功。
