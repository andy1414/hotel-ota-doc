# 交易接口契约

单一接口来源，2026-10-30。DTO位于ota-common的BookingFlowContracts；身份固定在渠道认证主体，Create不含channelCode。

| 调用方向 | 路径与请求 | 响应 | 鉴权 |
| --- | --- | --- | --- |
| channel → order | POST `/order/internal/booking/{channelCode}/quotes` QuoteRequest | Result，库存渠道报价视图 | X-OTA-Internal-Token，order booking.flow.internal-token |
| channel → order | POST `/order/internal/booking/{channelCode}/orders` Create | Result<OrderView> | 同上 |
| channel → order | GET `/order/internal/booking/{channelCode}/orders/{orderId}` | Result<OrderView> | 同上 |
| channel → order | POST `/order/internal/booking/{channelCode}/orders/{orderId}/cancel` Cancel | Result<OrderView> | 同上 |
| order → supplier | POST `/supplier/internal/booking/submit` SupplierSubmit | Result<SupplierResult> | X-OTA-Internal-Token |
| order → supplier | POST `/supplier/internal/booking/query` SupplierQuery | Result<SupplierResult> | 同上 |
| order → supplier | POST `/supplier/internal/booking/cancel` SupplierCancel | Result<SupplierResult> | 同上 |
| supplier → order | POST `/order/internal/booking/supplier-events` SupplierCallback | Result<Void> | X-OTA-Internal-Token，独立order booking.flow.supplier-callback-token |
| order → inventory | GET `/internal/rates/quotes/{id}/snapshot?channelCode=` | Result<QuoteSnapshot> | X-OTA-Internal-Token |
| order → inventory | POST `/internal/rates/quotes/{id}/cancel-confirmed` CancelConfirmation | Result，库存View | X-OTA-Cancellation-Token，inventory.quotes.cancellation-token |
| order → channel | POST `/channel/internal/booking/notifications` Notification | Result<NotificationAck> | X-OTA-Internal-Token |

库存既有create/hold/begin/outcome/get/release仍采用X-OTA-Internal-Token；取消归还BOOKED采用单独密钥，不能用普通release冒充供应取消证明。

SupplierResult.state为CONFIRMED/PENDING_CONFIRM/FAILED/UNKNOWN/CANCELLED/CANCEL_REJECTED/CANCEL_CONFLICT，只有definitive=true的FAILED/CANCELLED能自动释放占用。reason仅用于展示和诊断，业务分支绝不解析reason文本。SupplierResult结构化携带cancelRequestNo（关联取消请求号）、priorState（仅CANCEL_CONFLICT携带，固定为CANCELLED或CANCEL_REJECTED）与priorEventId（仅CANCEL_CONFLICT携带，固定为首次权威取消事件的eventId且不得等于当前冲突eventId）。CANCEL_REJECTED表示取消明确被拒绝，保持原预订、配额与资金，不能当原预订FAILED；CANCEL_CONFLICT仅记录后到相反取消证据并将订单置为REVIEW_REQUIRED，其本身绝不触发配额释放或退款；原事实作为独立事件收敛，若冲突证据先到且原事实尚未核实，订单保持现有配额与资金并通过原取消请求号查证恢复权威原事实。接入方不得把超时或简单未查到当确定失败。

支付/退款结果仅接受独立内部入口、明确配置的提供方与签名校验；TEST与REAL隔离。尚无真实接入时返回NOT_CONFIGURED，不模拟生产资金成功。

## 订单与资金入口补充

普通渠道/订单内部调用方不能用自己的凭据伪造供应回调，也不能修改平台策略。订单服务配置：

- `booking.flow.internal-token`：渠道→订单通用内部鉴权。
- `booking.flow.supplier-callback-token`：供应商服务转发已验签事件的独立鉴权。
- `booking.flow.admin-token`：支付策略、对账、通知失败查询与重放。
- `booking.flow.payment-signing-secret`：资金事件HMAC签名；单独于上述token。
- `booking.flow.test-payments-enabled`：默认false；当前只注册明确TEST提供方，真实资金接入为NOT_CONFIGURED。

| 方法/路径 | 用途 |
| --- | --- |
| POST `/order/internal/booking/{channelCode}/orders/{id}/payment-events` Payment | 已核验支付结果，额外要求X-OTA-Payment-Signature |
| POST `/order/internal/booking/{channelCode}/orders/{id}/refund-events` RefundResult | 已核验退款结果，额外要求同签名头 |
| POST `/order/internal/booking/admin/channel-policy` ChannelPolicy | 明确BEFORE_SUBMIT/AFTER_CONFIRM、支付提供方与支付期限 |
| GET `/order/internal/booking/admin/orders/{id}/reconcile` | 平台核对订单与配额状态 |
| GET `/order/internal/booking/admin/notifications/failed` | 失败通知列表 |
| POST `/order/internal/booking/admin/notifications/{id}/replay` | 显式重放FAILED通知 |

### 资金签名规范

采用HMAC-SHA256，UTF-8编码，签名输出64位小写十六进制。canonical为以下字段按顺序用单个LF连接，不追加末尾LF：

1. HTTP方法，固定POST。
2. 精确订单操作路径：`/order/internal/booking/{channelCode}/orders/{id}/payment-events`，退款则为`refund-events`。
3. provider。
4. eventId。
5. transactionNo；退款使用refundNo。
6. amount，规范为两位小数的普通十进制字符串。
7. currency。
8. state。

签名绑定渠道、平台订单及支付/退款操作，不能将相同金额的签名移到另一个订单。提供方+资金流水号在全局归属于唯一订单/操作；同一笔资金允许多个事件，事件编号同内容幂等、不同内容冲突。全额不同流水重复支付/退款或成功后迟到失败进入REVIEW_REQUIRED，不悄悄覆盖资金事实。

### 恢复与状态边界

- 本地订单、供应请求号、提交意图和快照先提交，再调用远端。库存hold/begin和供应submit均重用原始幂等号。
- 崩溃恢复先query；UNKNOWN时重新投递同一requestNo、同一快照的供应接入命令。供应接入记录存在则只查证，不再次调用外部book；缺记录才首次持久化并派发。
- 供应回调先落可靠Inbox再收敛。网络响应丢失、取消未确定不能被当作FAILED或CANCELLED释放配额。
- 取消按下单时政策；已提交且不可取消或已过截止时间拒绝自动取消。明确供应失败导致无法履约则独立协调退款。
- BEFORE_SUBMIT支付期限从创建计时，不得超过目前30分钟预提交配额期限。AFTER_CONFIRM在首次供应CONFIRMED时才启动付款时钟，异步待确认期间没有付款超时；重复确认不延长期限。渠道政策在订单中快照固定，修改政策只影响新单。
- 对账返回本地supplierState、实时查询的remoteSupplierState与difference；供应查询超时为UNAVAILABLE、未查明为UNKNOWN、响应归属或确定性非法为INVALID_RESPONSE，上述情况及本地待复核状态difference均为true，不把未知或缓存状态重复包装成“已对账一致”。真实资金对账接口仍未接入。
- 订单通知与状态更新同事务Outbox，按同订单版本顺序发送并核验ACK eventId；10次失败转FAILED，由平台查看/重放。
- 旧订单controller、旧超时/孤儿/供应商/渠道补偿任务及旧Outbox仅在booking.legacy.enabled=true时启动，默认关闭。

TEST支付及退款记录使用明确TEST提供方和TEST退款流水前缀。真实资金接口、真实供应凭据缺失不能解释为生产联调通过。
