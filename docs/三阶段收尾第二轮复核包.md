## 十、本轮新增问题与关闭要求

### 第二轮-01：以说明文本判定权威事实，且冲突分支仍执行取消副作用（P1）

位置：`ota-order/src/main/java/com/ota/cloud/order/booking/BookingFlowService.java:122–137`；`ota-supplier/src/main/java/com/ota/cloud/supplier/booking/SupplierBookingStore.java:143–148`。

订单用 `reason.contains("保留原结果CANCELLED")` 和 `reason.contains("保留原结果CANCEL_REJECTED")` 判断权威原事实；reason 还拼接了供应返回的自由说明。两段标记可以同时出现，例如原事实 CANCELLED，后到拒绝的说明引用“保留原结果CANCEL_REJECTED”。在冲突先到、订单本地尚无明确取消事实时，代码优先选择 priorRejected，错误保留预订并标记拒绝；反之，缺少、改写说明文本也会改变处理结果。当前契约没有结构化原事实及原事件身份，校验不能排除该歧义。

此外，当 priorCancelled 从文本得到 true 时，冲突分支直接调用 `ports.cancelled` 并置退款待处理，现有测试也断言冲突先到可触发一次库存归还和退款。该行为与交付说明“冲突证据不执行取消成功命令”和返工要求不一致，不能标为完全关闭。

### 第二轮-02：故障脚本绑定的旧事件可能被真实渠道标记 SUPERSEDED（P2）

位置：`scripts/booking-flow-smoke.py:346–355、373–376`；`ota-channel/src/main/java/com/ota/cloud/channel/booking/ChannelNotificationJob.java` 的最新版本检查。
